# 第一阶段运行与验收指南

当前只有设计文档。下面是后续代码必须支持的运行约定，相关目录、脚本和测试尚未生成，不能现在直接运行并期待成功。

## 前置条件

- Java21 JDK、项目内Maven Wrapper；Java21.0.6已在本机发现，开发前检查javac并选择适用补丁版本。
- Node24.12+的24.x版本；项目npm锁文件固定依赖。本机Node25不是本计划的锁定基线，不覆盖已有全局安装。
- PostgreSQL18；本机psql18.6可用，但未证明现有数据库服务可用。新建dental_dev与独立dental_test，禁止连接既有其他项目库。
- 微信开发者工具用于患者端；真实登录另需有效AppID、服务端密钥与合规网络配置。无真实账号时只运行明确的模拟身份测试，不能算真机验收通过。
- 安装新增工具优先D:/DevTools，项目在D:/GitHub/A-dental-clinic-system。应用代码不放入Spec Kit工具安装目录。

## 后续实现必须提供的命令

以下PowerShell命令以项目根目录为起点。密码及连接配置从本地环境变量注入，不把实际密码写在示例中。

```powershell
Set-Location D:/GitHub/A-dental-clinic-system/backend
.\mvnw.cmd verify
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=local'
```

后端local配置连接dental_dev，测试配置必须连接独立dental_test。Flyway启动迁移失败则服务不继续写库。
实现需提供仅local profile可运行的合成数据初始化入口，及一次性管理员引导命令；禁止生产自动seed和默认密码。

另开终端运行管理端：

```powershell
Set-Location D:/GitHub/A-dental-clinic-system/admin-web
npm ci
npm run typecheck
npm run test:unit
npm run dev
```

构建和浏览器验收：

```powershell
npm run build
npm run test:e2e
```

小程序使用开发者工具打开patient-miniapp目录，配置本地联调服务；真实真机测试使用HTTPS服务。不得以开发工具关闭域名校验作为生产配置。
上面的命令、脚本名称是实现任务的交付契约，尚未执行，不能记录为通过。

## 合成数据

建立A店、B店、一名跨店牙医、一名替诊牙医、两个前台、负责人、管理员和至少20名合成患者。
设置一个“本店前台+其他店库管”的兼岗账号，验证不能拼接权限。
提供检查评估等可预约服务、具体牙椅及设备、结构化营业区间；未知治疗先约评估。
基础预约政策已发布但限制关闭。额外建立启用限制的测试版本；签到提前30分钟、迟到15分钟仅为演示参数。
合成临床建议作为只读fixture，不能给真实患者制造既往病历。每次测试独立数据，未授权不清空用户数据库。

## 手工演示路径

1. 负责人进入A店，核验医生任职、服务和资源，发布明天排班。
2. 患者小程序匿名查看门店及熟悉医生；认证建本人档案后预约，直接得到已确认凭证。
3. 前台工作台看到同一记录，再为电话患者代办另一时段，不能挤占已约时段。
4. 患者改到不可用时段，观察原安排仍在；再成功改约，查看新旧关联。
5. 负责人登记医生停诊或设备故障，患者凭证显示待协调；前台发送方案，患者拒绝则不替换，同意后仍重新验证资源；资源恢复须人工核实（误登记撤销/已修复），不因预计结束时间已过自动恢复。
6. 在有效签到时窗扫码，再由前台重复签到，始终返回同一候诊号。
7. 前台核实取消和未到：已经签到离店不算未到，合成过号状态同样不记未到；默认政策不会处罚。
8. 在合成启用政策下验证边界、申诉豁免、到期与事件不重复利用。

## 自动化验证矩阵

| 验证组 | 对应规格 | 必须观察的结果 |
| --- | --- | --- |
| 排班资格与跨店缓冲 | FR-001/002/007；SC-001 | 不合格、重叠、未营业不发布 |
| 注册绑定与权限撤销 | FR-003/021；SC-005 | 同号不认领旧档、撤权即失效、注册上下文无业务权限 |
| 并发预约与幂等 | FR-006/007/008；SC-002 | 20人争一安排最多1成功，同键10次仅1记录 |
| 取消改约与停诊 | FR-010/011/013/014；SC-003 | 20次失败原有效安排保留，无隐式替诊 |
| 双入口签到 | FR-015/016/017；SC-004 | 唯一候诊，错店/过期/取消不可入队 |
| 政策与申诉 | FR-018/019/020；SC-006 | 未批准不限制，临界时刻、同版本计次、到期不重复触发 |
| 模拟渠道失败恢复 | FR-022/023 | 业务已提交不回滚，结果未知不假装送达，重启可发现待办 |
| 复诊及主治边界 | FR-004/005/024 | 收藏不变主治，复诊一计划一有效预约，取消不关闭目标 |
| 查询性能 | SC-007 | 20并发下记录p95及错误比例，不能以全部报错冒充可用 |

数据库竞争测试必须使用独立事务和同步起跑条件，不以顺序循环冒充并发。
使用可控时钟测试24小时整点、签到上下界和7天滚动边界，不修改整机系统时间。
测试“取消先完成”和“签到先完成”两种次序；最终取消可以合法发生在签到之后，但不能遗留有效候诊。不能误要求所有并发操作都只能一个返回成功。
测试改约新旧区间重叠时原子释放、临床已开始后拒绝取消，以及同患者重复预约。

## 数据迁移与云部署验收

- 从空测试库迁移成功，PK/FK、联合外键、唯一、排他约束及复诊活动预约/改约后继两个部分唯一索引实际存在。
- 上一版本样本数据升级后不丢历史，备份恢复到隔离库并核对数量及关键关联。
- HTTPS代理、静态网页、API和数据库内部网络分别验证；未购服务器时只记本地演练状态。
- 真实小程序登录、域名、扫码、订阅授权及隐私配置按平台核验后再签真机验收。
- 关闭模拟身份与seed，检查密钥未进代码、日志和公开文件；开放端口仅满足需要。
