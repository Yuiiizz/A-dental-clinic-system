# 采购验收与批次库存实施决议（2026-11-09）

## 现状与边界

源码核对：V001 已有 `supplier`，V018 仅增加 `suppliers.manage`；截至 V018，数据库没有 `stock_item`、`stock_batch`、`warehouse`、`purchase_receipt`、`purchase_receipt_line`、`stock_movement`。管理端 `/suppliers` 为真实接口，`WorkspaceView` 的“新增采购单、验收、库存”仍只改本地演示状态。Word 6.3.49–6.3.54 是目标数据字典，不得当作已迁移结构。

本批先实现**普通耗材的验收即过账**：品种和库位配置、实际收货核对、一次提交验收入库、按批次查看余额与来源。它是采购验收记录，不是采购订单、应付款、付款、财务税额或临床领用。药品、特殊管制品、设备资产、调拨、退货、盘点、报损、已过账冲销留后续独立批次；页面必须明确这些边界。旧 `/demo` 采购记录不得导入真实账。

## 已审定的首批规则

1. **结构**：新迁移 V019 只新增上述六张表、必要约束/索引和独立权限，不修改 V001–V018。沿用 Word 所列字段和类型；如为真实事务增加索引或约束，写入迁移说明与 Word 待同步清单。`stock_batch` 是批次主档，余额只由 `stock_movement` 求和，不存可任意改写的“现存量”。Word 中 `stock_movement.care_id` 指向尚未迁移的 `care_item`：首批保留可空列但不建假 FK、也不开放临床领用；后续新增临床成本层时补真实 FK。
2. **状态**：首批仅开放“一次核对后过账”，不开放草稿修改或作废已过账单。成功写 `purchase_receipt.state='已过账'`，同时写明细、批次和正向流水；任一步失败整体回滚。Word 中的“草稿、作废”是后续目标状态，不能在 UI 做假按钮。界面名称用“采购验收入库”，不要称“采购单已下单”。
3. **身份和权限**：`inventory.view` 默认显式授予 owner、inventory；`inventory.configure` 默认显式授予 owner、inventory；`inventory.receive` 默认仅授 inventory。所有门店数据还要由**同一角色**的门店 scope、本人有效已核实任职和营业已核验门店共同授权。sysadmin、frontdesk、dentist、finance 不借其他权限旁路。全局耗材目录配置仍须至少一个符合条件的门店 scope；读取仅返回必要字段。资格和权限在幂等锁前、后及必要行锁后复查。
4. **供应商与批次**：过账时重新核验供应商 `enabled=true`、核验人/时间存在、`valid_to` 不为空且不早于锁后取得的上海业务日期。历史空有效期不能被当作有效。耗材 `enabled=true` 且 `kind='耗材'`；库位启用且归属目标门店；批次到期日不早于业务日期。批次以 `(stock_item_id, manufacturer, batch_no)` 唯一；若已存在，`expires_on`、`holder_name` 等事实不一致则 409，不得覆盖旧批次。已有过账明细引用的批次事实字段不能被后续配置改写。
5. **请求与金额**：一次验收 1–50 行，每行有品种、库位、厂家、批号、效期、最小单位数量 `numeric(14,3)>0` 和实际单位取得成本 `numeric(14,4)>0`。拒绝浮点输入、超精度、溢出和未知字段；Java 使用 `BigDecimal`，展示金额按明确舍入规则到分。该金额是库存取得成本参考，不自动生成应付款或税额；进口品牌也不自动向患者加“进口税”。凭证号与内部验收单号分别保存，禁止写真实敏感证件信息到审计。
6. **幂等字段**：HTTP `Idempotency-Key` 只在 `operation_request` 以账号+操作+键作用域保存并比对规范化请求。Word 的 `purchase_receipt.request_key` 和 `stock_movement.request_key` 填服务端生成的内部唯一 UUID，**不复制客户端键**；避免全局 UQ 与分账号幂等作用域冲突。同键同内容已提交后重放只返回当前可见的权威单据，不重入库；同键异内容 409。不同键重复内部单号、同一验收明细重复入库由唯一约束兜底。
7. **锁与事务**：先鉴权、取幂等 advisory 锁，再按固定顺序锁目标 branch、supplier、warehouse（ID 升序）、stock_item（ID 升序）、现有 stock_batch（稳定键序）；锁后重查状态、有效期、归属和权限。批次首次创建的并发用按批次业务键派生的事务 advisory 锁串行化，数据库唯一约束兜底。收货单、明细、批次、正向流水、审计和幂等记录同一 READ COMMITTED 事务提交。不得吞数据库异常并伪装成业务 409，也不得承诺消除所有跨模块死锁。
8. **余额与来源**：`stock_movement` 首批数据库 CHECK 只允许“采购入库”正数流水，其他类型须由后续迁移连同完整业务约束开放；每条验收行仅一笔入库，对 `receipt_line_id` 建部分唯一约束。已过账事实不可无痕 UPDATE/DELETE。余额查询必须关联 `purchase_receipt.state='已过账'`，按批次+库位求和，不能把事务中或异常遗留的草稿流水当成账面库存；列表可按品种汇总，但详情必须能追到验收单、供应商、批号、效期、经办人与过账时刻。零库存批次可显示但不得伪装有货。首批无领用/调拨，所以“可用库存”仅为账面余额，不表示临床可直接使用。
9. **候选与历史**：配置停用仅阻止新的验收，历史单据和流水保留。未来若做退货、报损、调拨、领用，只追加有依据的反向或成对流水；同成本层同库位余额不能负数，领用优先近效期且需再次检查合格/有效。不要在本批通过直接改余额提前实现这些流程。

## 必须暴露的最小真实界面

- 耗材目录：列表、建档与状态/规格详情；门店库位：列表、建档。
- 验收入库：选择授权门店、已核验供应商、库位、耗材，录入批号/效期/数量/单位成本及供货凭证，显示计算金额和明确的“确认过账”二次确认。
- 验收记录：分页、详情、同键手动恢复；库存：按门店/库位/耗材/批次显示余额与来源。没有授权、无库位、供应商过期、数据结果不明均给明确提示。旧演示页面保留标识或从正式导航移除，绝不能混合真实与演示数量。

## 真实 PostgreSQL 验收矩阵

1. inventory 本店完成“目录/库位 → 验收入库 → 批次余额/来源”全链，owner 只在显式授权范围配置/读取、不能过账；frontdesk、dentist、finance、sysadmin、跨店/跨角色拼接均拒绝。
2. 同键同内容并发只一单一组流水；同键异内容 409；响应丢失后同键重放零增量；撤权后重放拒绝；业务失败不留单、批次、流水、审计、幂等占位。
3. 过期/空有效期/停用供应商，停用耗材或库位，错门店库位、已过期/隔离/召回批次、批次事实冲突均拒绝且零写入；等锁跨午夜后重新检查效期。
4. 相同批次不同验收可重复进货并累计余额；同一验收行不能重复入库；批次唯一并发最终只有一份。分页不漏不重；数据库故障不伪装业务冲突。
5. 数量三位、单位成本四位、小数舍入和边界、超大值、负数、零、未知字段、空行/超 50 行、重复行号均有 HTTP 与数据库断言。
6. 页面使用真实后端和隔离教学库走查，确认创建后刷新余额、冲突后保留输入、403 清可见缓存、不自动重试结果不明请求；不能只凭 mock 单测宣称闭环。

实现完成后再把实际表、权限、状态、金额口径和验证范围同步到 OpenAPI、`api.md`、两份字段清单、Word 6.3.49–6.3.54 与 7.6；未实现的后续状态继续标为目标设计。
