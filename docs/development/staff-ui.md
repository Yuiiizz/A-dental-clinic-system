# 员工管理页面（T025-UI-A）

> 当前补充（2026-11-20）：下文记录最初 T025-UI-A 验收边界；本日新增资格事实受控读取及首次审核/撤销入口，以下“尚未提供审核入口”等旧批次表述仅描述当时状态。见文末当前补充。

实现日期：2026-10-27。范围仅列表、详情、建档三个既有后台接口；不含修改、离岗、任职写入、本页资格审核/撤销入口、医生服务或排班。后端资格撤销已经实现；未完成的是本页面审核/撤销入口、rejected 重核和下游预约/排班协调。

## 入口与路由

- `/staff-members`，路由名 `staff-members`；首页对 `owner` 角色展示“员工管理”链接。
- `owner` 角色不等于 `organization.responsible_staff_id`：页面明确提示“仅组织负责人可提交”，最终由服务端 `staff.manage_global` + 组织负责人检查判定；不伪造权限字段，不新增权限探测请求。

## 对接接口

- `GET /api/v1/staff/staff-members?cursor=&limit=`：真实 `next_cursor` 分页，默认后端 20/最大100；前端不添加搜索、排序或筛选。
- `GET /api/v1/staff/staff-members/{id}`：受控基本资料、可见门店任职、资格摘要。
- `POST /api/v1/staff/staff-members`：`Idempotency-Key`；可选一份 pending 资格；不创建账号、角色或任职。

## 页面行为

### 列表

- 显示姓名、人员类型、岗位、在岗状态、主档版本。
- 刷新、加载更多、加载中、空列表和错误重试。
- 旧 `next_cursor` 响应通过代次丢弃；跨店任职同一 `staff_id` 去重；列表失败保留上次已确认数据并提示结果未确认。

### 详情

- 仅在选中员工后显示；可空 `practice_no` 显示“未填写”，不显示 `undefined`。
- 门店任职只显示接口可见范围；资格摘要显示资格类型、审核状态、起止日期/无期限确认、资格版本和 `effective`。
- `effective` 只表示“该资格自身审核状态 + 日期有效”，页面明确不代表可以接诊或已有排班授权。
- 不展示证书原文、账号、角色、其他门店或患者资料。

### 建档

- 姓名、人员类型、岗位、执业编号；牙医执业编号必填。
- “同时录入一份待核验资格”未勾选时不发送 `credential` 字段；勾选后才发送资格区块。
- 资格日期为 `YYYY-MM-DD`，截止日期不能早于起始；确认无期限时清空并禁止截止日期；录入只是 pending，不是审核通过。
- 明确提示：建档不创建登录账号、不分配角色、不建立门店任职。
- 成功后清空草稿、刷新列表并打开新员工详情；失败/结果不明保留原输入和幂等键。
- 提交在途禁用整组建档输入（含人员类型、资格开关、日期和按钮），并用操作 id、会话/reset、草稿代次和选择意图代次保护：旧完成回调不得清掉提交后的新草稿、设置旧错误、清掉新提示、释放新 busy 或强行切回旧员工。
- 建档成功后的列表刷新失败/401/403/结果未确认时不打开详情；已确认建档成功与列表刷新失败分开提示，不把刷新失败误报成建档失败。
- 用户选择使用意图代次，不只比较 ID；建档等待期间 A→B→A 仍视为主动改变选择。列表/详情加载期间员工切换按钮明确 disabled，不出现可点但静默忽略。
- store 与页面两层防重复提交；不改写后端校验结果。

## 会话、代次和幂等

- 页面使用 `useStaff` 的列表/详情/建档独立代次；会话身份变化（退出、换账号、重新登录、身份未确认）立即清空旧列表、详情、草稿和幂等键。
- A→B→A、并行刷新、旧分页和旧详情响应按代次丢弃，不覆盖当前页面。
- 401 通过现有 session store 重新核验身份，不直接自行登出。
- 列表或详情读取 403 使用共享失效：清列表、分页、选中项和详情，并推进列表/详情代次，使在途读取不能复活；保留合理建档草稿，不登出。详情 404 只局部清除目标，不当作全范围撤权。
- 同一建档内容在超时/网络失败/5xx/畸形 2xx 后保留原幂等键；内容变化或明确开始新建时换键；不自动重发，不把结果不明显示为确定失败。
- 发送前本地校验失败（`VALIDATION_FAILED`）明确提示修正输入，不归为“服务器结果不明”；已发出请求的畸形 2xx/解析失败、网络/超时/5xx 才是结果不明。
- 成功后才清空草稿并跳转/刷新；旧建档请求迟到不得清空新草稿、设置旧错误、清除新上下文提示或显示错误成功提示。
- 建档后的详情打开在每次 await 后重新核对操作 id、会话/reset、草稿和选择意图；不重用旧布尔值。`clearFields` 主动清空不计为新的用户编辑，正常成功仍可打开新详情。

## 资格状态表述

- `pending` 显示“待审核”，`verified` 显示“已核验”。
- 后端撤销后仍使用 `rejected`，且摘要不返回最新动作；页面显示中性的“未通过/已撤销”，并说明不能区分首次驳回或后续撤销，不能推断撤销原因。
- 后端资格撤销已实现，但本页面尚未提供审核/撤销入口；摘要仍不返回最新动作，不能区分首次驳回或后续撤销、不能推断撤销原因。rejected 重核和下游预约/排班协调也尚未完成。
- 不新增历史查询接口，不在本页面扩展审核/撤销功能。

## 契约缺口

- 列表/详情/建档以外（PATCH、任职写入、本页资格审核/撤销入口、医生服务）未开放，UI 不展示入口；资格撤销后端已实现，不代表本页面入口已闭环。
- `owner` 与唯一组织负责人无法从 `/auth/me` 直接区分；页面只能提示并由服务端 403 最终判定，没有新增权限探测接口。
- 审核 UI 需要的受控证件事实读取尚未设计；本页面不读取或展示证书原文。
- 资格摘要不返回最新 `revoke/reject` 动作，仅凭 `rejected` 无法区分；这是当前契约缺口，UI 只能中性显示。

## 当前补充：资格审核入口（2026-11-20）

员工详情仍只含资格摘要。具有 `owner` 角色的页面会显示“查看核验资料”，实际读取须通过服务端唯一组织负责人授权；门店负责人收到 403。只有显式点击时才调用单条 `facts` 接口，显示证书编号、类别、日期、状态和当前版本；切换员工、退出或切换会话、关闭面板时清除这份敏感资料，迟到响应不能复活。成功读取在服务端写不含证书编号的访问审计，响应 `no-store`。

负责人可对 pending 资格作首次通过/驳回，对 verified 资格作撤销；提交实际依据和读取到的版本，服务端仍负责终态、日期、权限和并发校验。网络/超时/5xx 结果不明时保留相同内容的幂等键，不自动重发；409 后要求重新读取事实。rejected 重核和证件事实修改仍未提供。页面不能证明证件真伪，须由经办人实际核对原件或授权材料。

隔离 PostgreSQL 后端全量 422 项通过；管理端 Node 24 的 typecheck、259 项全量单测和生产构建通过。API 和网页镜像已更新至云端，公网首页与公开门店接口 200、未登录受控接口 401；组织负责人登录后的核验点按仍待人工验收。
