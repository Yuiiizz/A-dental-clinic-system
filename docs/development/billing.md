# 收费票据（真实线下登记）

日期：2026-10-28。范围是**线下受控收费登记**，不是支付渠道接入，也不是税控正式发票。

## 数据表

- `bill`：应收总额、已登记收款、状态、版本；金额均为整数分。
- `bill_item`：项目、数量、单价、金额。
- `payment`：现金/银行卡/微信线下登记/其他线下；登记人、时间、备注。
- `refund`：退款申请与处理状态。
- `invoice`：票据申请、类型、税号、税率/净额/税额、票据号、红冲引用、作废信息；状态待开票/已开票/已拒绝/已作废。

## 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/v1/staff/billing` | 账单、已完成就诊、收款、票据 |
| POST | `/api/v1/staff/bills` | 从已完成就诊创建账单 |
| POST | `/api/v1/staff/bills/{id}/payments` | 分次登记线下收款 |
| POST | `/api/v1/staff/refunds` | 提交退款申请 |
| POST | `/api/v1/staff/refunds/{id}/process` | 财务登记线下退款完成或拒绝及依据 |
| POST | `/api/v1/staff/invoices` | 提交人工票据/税务票据登记 |
| POST | `/api/v1/staff/invoices/{id}/issue` | 人工登记开票号码 |
| POST | `/api/v1/staff/invoices/{id}/void` | 作废票据 |
| POST | `/api/v1/staff/invoices/{id}/red` | 红冲已开票票据 |
| POST | `/api/v1/staff/treatment-plans/{id}/bill` | 从已接受治疗计划生成账单 |
| GET | `/api/v1/me/billing` | 用户查看本人账单、收款、退款、票据 |

## 规则

- 账单必须来自已完成就诊。
- 收款金额必须大于 0 且不能超过待付余额；全部付清后状态为“已收款”。
- 票据只有“已收款”账单可申请，申请后为“待开票”。
- 票据按购方类型（个人/单位）和税务处理（应税/免税/零税率/不征税）分别校验；不是所有票据都强制税号或正税率。
- 应税票据才要求税率和净额/税额拆分；免税/零税率/不征税税额为 0，净额等于已收金额。
- 红冲申请只创建待开票红字记录，原票保持已开票；红冲票登记完成依据后才将原票置已红冲，活动红冲由唯一索引防重复。
- 系统不自动猜测医疗项目税率，也不连接税控平台。
- `billing.manage` 已授予 frontdesk/finance；owner 不自动旁路收费权限。退款处理另需 finance 的 `billing.refund_process`。
- 不调用微信/支付宝/银行卡支付接口；页面和文案必须明确“线下登记”。
- 退款申请先占用可退额度；财务核对线下退款凭证后，可登记“已退款”或“已拒绝”并填写处理依据。处理结果不可重复提交。账单保留累计收款，另按实际退款累计显示“部分退款/已退款”；票据红冲或作废仍须独立处理。

## 税务边界

V011 的税率、净额、税额是人工确认的快照，不实现税控开票、发票查验或自动税务计算。正式发票类型必须人工填写税号并显式拆分金额。

### 退款申请额度补充
申请在账单行锁内同时检查账单与指定付款的剩余可退额度；待处理、已退款申请占用额度，已拒绝不占用。指定付款必须属于本账单且为已登记状态。财务登记完成时保留 `paid_cents` 作为累计收款，退款金额单独累计；不得把申请视为到账。


### Codex 收款幂等（2026-10-29）
