# 普通耗材验收入库：后端与管理端

V019 六张表已接入真实后端接口。管理端 `/inventory` 现在读取普通耗材目录、本店库位、已过账验收单、批次账面余额；库管可人工核对后一次验收入库，owner 仅可维护目录和库位。原工作台内存样例仅留在本地开发演示模式，正式导航已转向真实页面，不能拿其样例数值解释真实库存。

## 接口与权限

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| GET/POST `/staff/stock-items` | `inventory.view/configure` | 全局普通耗材主档；至少一条有效门店授权链 |
| GET/POST `/staff/warehouses` | `inventory.view/configure` | `branch_id` 必填，只见本店库位 |
| GET/POST `/staff/purchase-receipts` | `inventory.view/receive` | 列表只读已过账；创建为一次性过账 |
| GET `/staff/purchase-receipts/{id}` | `inventory.view` | 明细、批次、成本来源；未过账/不可见 404 |
| GET `/staff/stock-balances` | `inventory.view` | 仅已过账正向流水，按库位和批次汇总 |

owner 可配置、读取，不可验收入库；inventory 三项权限均有。授权要求同一角色的权限和门店范围、操作者有效已核实任职、已核验营业门店及营业中的经营主体。前台、牙医、财务、系统管理员不因其他角色获得本功能权限。读写均使用员工 Cookie；变更还需 CSRF，创建还需 Idempotency-Key。

## 写入与恢复

数量为 `numeric(14,3)` 正数，单位取得成本为 `numeric(14,4)` 正数；1–50 行，行号不得重复。请求不接受服务器字段或未知字段。过账前按 branch → supplier → warehouse ID → stock_item ID → batch 业务键的顺序取事务锁，锁后取得上海业务日期并重查权限、供应商资质、启用状态、库位归属、耗材类别和批次有效性。收货单草稿、明细、每行一条等量正向流水、转已过账、审计和幂等记录在同一 READ COMMITTED 事务中提交；失败整笔回滚。

同键同内容重放只返回当前仍可见的权威单据，不再次入库；同键异内容 409。内部 `request_key` 为服务端 UUID，不复制客户端幂等键。客户端响应未知时应保留原键，人工确认或同键重试，不能换新键盲目再过账。余额必须关联已过账单据，不能只汇总所有 `stock_movement`。金额为取得成本参考：原始 `数量 × 单位成本` 逐行求和后，HALF_UP 舍入到分；不代表已付款、应付款或税额。

## 边界

本批不开放药品、草稿编辑、作废、退货、调拨、盘点、报损、临床领用、设备资产、付款或自动税务处理。供应商主档复用既有接口。管理端列表和详情均为真实接口，采购验收表单带原幂等键，结果不明时保留输入供人工核对；切换会话或门店会清空旧数据与草稿。小程序不接入库存。Word 6.3.49–6.3.54 和开发验收章节已同步实际权限、过账规则与未开放状态；完整目标模型仍作为后续设计。

## 真实浏览器与数据库验收（2026-11-10）

在一次性 PostgreSQL 18.6 集群中，先由应用 Flyway 执行 V001–V019，再导入虚构教学数据；仅在该隔离库中为库管测试账号设置随机密码。Edge 浏览器通过管理端正常登录页取得员工 Cookie 和 CSRF，进入 `/inventory` 读取真实供应商、耗材及库位，提交一张新验收单，并在“批次余额”“验收记录”两页回查。浏览器无 pageerror，登录后的业务 API 无 4xx/5xx。数据库核对新单据、明细、入库流水各恰好 1 条，新批次余额为 3.000 件；取得成本为 ¥42.75。服务和数据库集群已停止，未连接现有开发库或真实用户库。该结果只证明本次库管验收入库链路；其他角色、退货、领用、盘点和小程序库存并未因此验收。
