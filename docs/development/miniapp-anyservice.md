# 小程序无自有域名接入：AnyService（待云端验收）

## 当前状态

小程序统一 HTTP 客户端已支持两条受控路径：未配置云接入时沿用 `wx.request` 与现有本地 `API_BASE_URL`；配置 CloudBase 环境 ID 和 AnyService 服务标识后，使用 `wx.cloud.callContainer` 调用同一套 `/api/v1` 后端接口。患者 Bearer、`Idempotency-Key`、错误状态和响应解析保持原有语义。云端已新增 AnyService 路由；没有改动现有服务器、数据库或已发布的小程序。

公开只读接口已在开发者工具和手机微信预览中通过云路由读取，不代表已完成微信登录、预约写入、微信审核或老师本人访问。

**2026-11-20 历史记录：**已购买的云开发环境在微信开发者工具“使用已有腾讯云环境”中显示“暂不支持选择 PostgreSQL 环境”。这一选择器限制后来通过原生云调用实测澄清，见下文。CloudBase 的 PostgreSQL 环境与本项目轻量服务器内的 PostgreSQL 是两套独立资源，本项目不需要迁移数据库。

**2026-11-21 实测：**该付费环境的云开发控制台“小程序认证”显示当前小程序“授权成功”。已在同一环境创建 AnyService 服务 `dentalapi`，公网 HTTPS 源站为 `1.15.110.181:443`。微信开发者工具普通编译后，在小程序调试控制台通过 `wx.cloud.callContainer` 调用 `/api/v1/public/branches`，收到 HTTP 200 和云端两家虚构门店的分页响应。因此 PostgreSQL 环境虽不能在开发者工具的“使用已有腾讯云环境”选择器中选中，当前 AppID 的原生云调用已通过公开接口实测。登录、鉴权头、写操作、真机和体验版仍未验证。

**同日手机预览：**开发者工具生成了短时预览二维码；用户手机微信打开后，诊所介绍页显示后端维护的云栖门店、滨江门店及云端门店资料。页面下方另有明确标记“演示数据·本地模拟”的展示区，该区不作为云端验收证据。手机只读链路已通过；患者登录、带身份的读写、老师账号扫码权限及长期可用的体验版二维码仍待验收。开发者工具短时预览码不能直接作为老师交付二维码。

**同日登录与界面更新：**服务器曾返回 `WECHAT_NOT_CONFIGURED`；管理员在服务器本地配置小程序 AppID/AppSecret 并重启 API 后，用户报告手机微信登录成功。此为用户手机反馈，尚未独立验收登录后的预约、记录与费用。源码新增首次登录需建档时的弹窗引导，以及个人信息页的“退出登录”：调用 `/auth/logout` 成功后清空本机会话。没有提供“注销账号”，因为当前后端没有账号销户及病历保留规则的完整流程；退出登录不删除档案。修改后类型检查和 16 文件、126 项单测通过；新界面尚未重新生成真机预览码。

## 为什么选这条路径

腾讯云官方文档说明 AnyService 可以将现有上海地域 Lighthouse 轻量主机接入小程序，不迁移现有服务，也不要求自有域名或小程序请求域名白名单。现有小程序普通 `wx.request` 不能直接把公网 IP 当正式合法域名使用。

- [腾讯云轻量服务器接入指南](https://cloud.tencent.com/document/product/1207/122538)
- [AnyService 产品说明](https://cloud.tencent.com/document/product/876/122892)
- [AnyService 使用指南](https://docs.cloudbase.net/anyservice/usage)
- [AnyService 套餐与地域 FAQ](https://docs.cloudbase.net/anyservice/faq)

## 安全与可用性边界

- 服务端继续依据既有患者 Bearer 授权；不把 `X-WX-OPENID` 等网关头直接当作已登录身份。
- 云网关连接失败、超时和已发出写请求的结果不明，不自动重试写操作或换幂等键。
- 当前源码已填入环境 ID 和服务标识，默认客户端启用云调用；本地隔离测试仍可显式注入 `cloudAccess: null` 沿用 `wx.request`。发布前还须验证登录及写操作。
- 管理网页通过公网 IP 的访问方式与小程序 AnyService 接入相互独立。
- AnyService 所需套餐与可能费用以当前账号控制台和腾讯云官方计费页为准；免费环境到期风险须在老师验收前核实。
