# 非部署功能核对（2026-11-02）

> 本页保留历史批次记录；当前链路状态与课堂演示优先级见 [2026-11-20 业务链路缺口核对](chain-gap-audit-20261120.md)。

本清单只以当前源码和已运行的检查为依据。页面出现入口不等于后台业务完成；`/demo` 的数据不作为验收证据。

## 已接真实数据的主要路径

- 员工登录与权限、门店、员工主档、排班配置、前台患者检索与选择、预约、临床记录、治疗计划、收费与票据均已有真实接口和部分管理页面。
- 患者端已有真实预约、就诊与治疗计划读取；费用页本轮接入本人账单、收款、退款和票据。
- 退款申请与财务人工处理结果本轮接入真实数据库；正式支付渠道、电子发票或税控平台均未接入。

## 尚需实现或验收的非部署内容

1. `WorkspaceView` 中的采购、库存、供应商、设备资产、折旧、经营统计、患者联系等仍使用本地演示数据或简化交互；需逐项补真实迁移、权限、接口、页面和隔离测试。
2. 管理端资格审核/撤销、医生服务范围、诊椅设备和预约政策等虽有部分后端能力，页面及真实浏览器操作仍需逐项核验，不能把演示页算作完成。
3. 患者小程序仍有演示门店与医生介绍等页面；需以真实门店、医生、排班数据替换并在微信开发者工具运行检查。
4. 真实浏览器中，前台检索或建档 → 核验 → 选择凭证 → 预约，以及收费与退款的端到端操作仍待验证。
5. 收款目前是线下人工登记。若要真实线上收款、渠道退款或正式电子发票，需独立设计、接入和验收，不能沿用演示按钮。
6. 设计 Word 的退款处理、费用页和后续新增模块须在功能稳定后同步，避免报告声称尚未实现或过度承诺。
