# 数据库迁移与验收（2026-10-22）

## 已实现范围

V001__baseline.sql 创建42张基线依赖表，先建表再加外键以解决循环引用；采用当前最终字段字典，而不是旧报告SQL。V002__runtime_constraints.sql 创建6张运行辅助表，补充字段检查、排他约束、部分唯一索引及7个角色定义。总计48张业务表、386个字段；Flyway另建自己的版本历史表，不能误计为业务表。仅初始化角色定义，不创建真实患者、员工账号、收费数据或临床记录。

BIGINT单列业务主键采用GENERATED BY DEFAULT AS IDENTITY；联合主键及共享主键不生成独立序列。UUID凭证及幂等编号由服务端生成。外键禁止级联物理删除历史。历史导入若指定显式主键，须独立处理序列推进；本轮合成测试显式ID不代表生产导入流程。

本项目尚未发布数据库版本，所以V001直接包含合并后的基线字段（含confirmed_dentist_id等），V002不重复新增这些列。六张新表及运行约束仍由V002添加。已经部署后，禁止修改已执行迁移，后续用V003等追加；这两份脚本不是对任意旧报告数据库的通用导入器。迁移测试当前统计 **442 个字段、54 张业务表**（含 V009 收费票据表增补）。

V003（2026-10-22，T014）追加固定权限目录与角色门店授权所需数据（不改 V001/V002）。V004（2026-10-23，T017-B）为 `identity_challenge` 追加 `branch_id`/`revoked_at`，重写 `ck_identity_challenge_purpose_fields`（`patient_binding` 要求 `patient_id`/`issued_by` 非空且 `branch_id IS NOT NULL OR revoked_at IS NOT NULL`），新增每患者至多一条待用绑定凭证的部分唯一索引 `uq_identity_challenge_active_binding`，并新增 `patients.bind_issue` 权限仅授予 `frontdesk`；历史绑定行缺 `branch_id` 不任填门店，统一撤销后用约束过渡。V005（2026-10-24，T024-A）仅给 `branch` 追加 `license_no_expiry_confirmed boolean NOT NULL DEFAULT false`，并新增 `branches.create` 权限且仅授予 `owner`；不新增表，不改已执行迁移。V006（2026-10-26，T025-A）给 `staff` 追加 `version integer NOT NULL DEFAULT 1` 与正数检查；将 `credential.verified_by/verified_at` 改为可空，新增“成组为空/成组有值”和“verified 必须有核验人时间”的检查；新增 `staff.manage_global` 权限且仅授 `owner`。V009（2026-10-28，阶段3）新增 `bill`、`bill_item`、`payment`、`refund`、`invoice` 五张线下收费/票据登记表，金额以整数分保存；不接支付渠道、不生成正式发票。V007（2026-10-26，T025-B1）给 `credential` 追加 `version integer NOT NULL DEFAULT 1` 与正数检查，新增追加式 `credential_review` 表（submit/verify/reject、from/to状态、执行人、依据、服务端时间、resulting_version）及外键/索引；不补造迁移前审核历史，不改旧迁移。

## 数据库保证

- 患者/员工账号身份恰有一个；角色门店范围联合引用实际账号角色；价格历史联合引用门店服务。
- 确认医生、排班及门店通过联合外键保持一致，候诊门店与预约门店亦由联合外键约束。
- 活动预约按患者和确认医生防时间重叠，资源占用另含周转时间；半开区间允许紧邻预约，待协调不自动释放占用。
- 排班、营业区间及主治任期另有排他约束；复诊活动预约、已确认改约后继、活动改约方案、当前限制和当前主治有唯一性保护。
- 第一阶段appointment_item每预约至多一个项目；未来支持组合项目须显式修改规格和追加迁移。
- 政策草稿批准信息可空，发布必须完整；限制默认关闭。资源解除须恢复人、时间、方式、依据完整，保留登记人。
- 幂等键唯一域为账号+操作+客户端键。预约内部UUID不等于客户端幂等键。

## 升级与失败恢复

V002对已确认等历史预约先核查排班、门店和确认时间；从关联排班回填确认医生，不用意向医生猜填。无法核实时中止并给出最多20个异常预约编号，整次迁移回滚。其他脏数据由约束添加失败显式阻断，不能自动删除数据以迁移成功。

事务隔离仍须服务层保证：资格、任职、停诊、跨店交通缓冲、限制事件归属、资源需求数量、预约必须含项目、历史自关联无长环、授权和通知协调不能全部靠单表CHECK表达。业务写事务按规格锁顺序执行；数据库排他竞争可能返回23P01或40P01，后续须有限重试整个事务并重新校验权限、幂等和号源，不能只重试一条SQL。

开发规格还修正了资源不可用边界：候选[s,e)仅在禁用开始<e时相交，等于e不冲突；预计禁用结束仍不自动恢复。Word暂不修改。

## 实际验证

独立PostgreSQL18集群执行28项测试，0失败、0错误、0跳过，其中10项迁移测试覆盖：

- 逐字段核对全部386项类型、长度、数值精度和可空；逐项外键/单列唯一性与字典一致。
- 48张业务表、7角色、迁移重复执行无新增动作。
- V001已有预约升级后保留数据并从排班正确回填，意向医生不被覆盖。
- 无法核实的升级中止并回滚，辅助表不半途遗留。
- 账号身份、过敏说明、草稿发布条件、角色门店关联拒绝非法数据。
- 患者、医生、资源冲突与相邻时段；真实并发预约仅一条成功。
- 复诊活动唯一性、取消后可重新预约、曾确认改约后继仍保持唯一、跨账号幂等键可复用。
- 资源恢复审计成组填写。
- 启动Spring Boot实际执行Flyway；已补spring-boot-starter-flyway，避免只有Flyway库而没有Boot自动配置。

执行命令沿用database-tests.md。测试角色和实例为一次性隔离环境；本轮未连接既有数据库，未部署云端。

## 云端部署衔接

迁移随后端打包，不依赖开发电脑上的Python。部署前在隔离恢复库试迁移，备份后使用专用迁移凭证；运行账号与迁移账号的最终授权在部署阶段落实。需要PostgreSQL可用的btree_gist扩展，云端权限不足时由数据库管理员预装到public，不能关闭排他约束代替。不要给互联网开放数据库端口。具体腾讯云实例、域名和证书待后续部署确定。


## V009 收费票据基线（2026-10-28）

新增 `bill`、`bill_item`、`payment`、`refund`、`invoice` 五张表，金额使用整数分。该迁移只建立线下受控收费、退款申请和人工票据登记结构，不接支付渠道、不生成税控正式发票。

测试统计：13 个迁移版本、56 张业务表、484 个字段。


## V010 治疗计划（2026-10-28）

新增 `treatment_plan`、`treatment_plan_item`，支持诊断、牙位、阶段、项目明细、患者确认和执行进度。金额为整数分；计划完成不自动生成账单。


## V011 发票税务字段与财务权限（2026-10-28）

为 `invoice` 增加票据类型、购方税号、税率、净额、税额、票据号、红冲引用和作废字段；新增 `billing.manage` 权限并授予 frontdesk/finance。税额必须人工确认，系统不猜测税率、不接税控系统。


## V012 治疗计划账单关联与红冲（2026-10-28）

`bill.plan_id` 关联治疗计划并建立唯一索引；`invoice` 支持负数红冲票、原票已红冲状态。计划只有患者接受后才能生成账单，且一个计划最多一张账单。


## V013 临床权限拆分与票据税务策略（2026-10-28）

新增 `clinical.record`、`clinical.plan` 并仅授予牙医；新增票据购方类型、税务处理、红冲完成依据字段；红冲申请不再直接修改原票，红冲完成登记后才置原票已红冲。

## V018 供应商档案权限（2026-11-09）

复用 V001 已建的 `supplier` 表，新增 `suppliers.manage` 权限，仅默认授予 inventory/owner。供应商资料真实入库后仍不能把本地演示采购、库存、成本视为已实现；这些需要独立的业务表、审计及验收。

## V019 普通耗材验收入库结构（2026-11-09）

新增 `stock_item`、`stock_batch`、`warehouse`、`purchase_receipt`、`purchase_receipt_line`、`stock_movement` 六张表及 `inventory.view/configure/receive` 三项独立权限。数据库约束保护批次唯一、库位归属、每行唯一正向入库、验收数量一致、先写明细流水再过账、已过账单据与流水不可无痕修改。首批流水类型仅允许“采购入库”；其他库存动作需以后续迁移连同事务约束开放。`care_id` 保留可空列，因 `care_item` 尚未迁移，当前没有物理外键，也没有临床领用接口。2026-11-10 已接入普通耗材目录、库位、验收入库与余额的真实后端接口。管理端 `/inventory` 后续也已接通真实接口，并在隔离 PostgreSQL 与 Edge 浏览器中完成库管登录、验收入库和余额回查；这不代表云端库管账号已激活，也不代表领用、盘点或成本闭环已实现。详细边界见 [普通耗材验收入库](procurement-inventory.md)。

## V020 前台签到核验依据（2026-11-10）

`queue_ticket` 增加可空的 `verification_basis`、`exception_reason`，保存前台现场核验依据及超窗或未配置窗口的人工理由。历史票据和后续自助签到可空；新前台签到由服务端要求依据，并在需要时要求异常理由。旧迁移未修改。

截至 V020，隔离 PostgreSQL 验证为 20 个版本、562 列；这是当时的历史统计。

## V021 复诊计划可选预约项目（2026-11-18）

仅为 `followup_plan` 增加可空 `service_item_id` 外键及非空值索引，不回填旧计划，不修改已有复诊状态或预约。医生可指定其当前启用的可预约项目；患者从计划预约及改约时必须使用指定项目，未指定的旧计划仍可按原规则选择。上线前须先备份并验证归档；Flyway 执行后核对旧计划仍为空值且数量不变。

V021 后目标为 21 个版本、563 列；最终测试与云端核对结果以本轮实际验证记录为准。
