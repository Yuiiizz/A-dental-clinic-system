## 后续编码要求

1. PostgreSQL 18 保持不变，不为容器化改用 H2 或删减关系、排他约束。镜像版本需在实施时明确固定，不使用 latest。
2. 应用连接配置与容器初始化配置分开管理。仅复制 env.example 不会使 Spring Boot 自动加载变量；须由启动器明确注入。
3. Windows 后端连接容器映射端口；后端与数据库同处容器网络时使用服务名。两个场景分别配置，不改业务代码。
4. 新增路径通过配置或跨平台路径 API 处理；Linux 大小写敏感，导入名和文件名必须一致。Shell 与 Maven Wrapper 使用 LF。
5. 容器就绪后仍须验证迁移、扩展权限、数据持久化及重启恢复。数据库健康检查不能代替业务迁移成功。
6. PostgreSQL 数据卷不等于备份。用匹配版本工具做独立备份并验证恢复；不得直接把 Windows 数据目录当作 Linux 数据目录挂载。
7. 云端不公开数据库端口；应用运行权限与迁移所需权限在部署阶段核定。生产禁用 mock/seed，密钥不进源码、镜像或日志。
8. 测试使用独立临时数据库，保留现有测试身份校验；禁止复用开发或真实患者数据库运行清理脚本。

## 切换时的验收顺序

- 安装并核对 WSL2/Docker 环境，编写并检查数据库 Compose 配置与环境变量模板。
- 启动空的开发数据库，验证健康检查、Flyway 和 btree_gist 等实际依赖。
- 如需旧数据，备份并恢复到新环境；核对数据与约束后再切换连接，保留原库以便回退。
- 在独立测试环境执行后端数据库测试，再进行真实双端 HTTP 联调。
- 重建容器验证持久化，另做一次备份恢复演练。
- 云端再核对 Linux 构建、网络、HTTPS、Cookie/CSRF 和微信合法域名；完成前不声称已部署。

这些工作是后续部署验收项，不影响当前门店、排班和预约功能开发，也不改变其业务需求或任务完成状态。
