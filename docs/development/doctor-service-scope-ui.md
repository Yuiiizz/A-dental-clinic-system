# 医生服务范围配置（2026-11-19）

管理端 `/scheduling?tab=scope` 使用现有 `GET /staff/scheduling` 的医生、项目与范围数据，以及 `PUT /staff/scheduling/staff/{staffId}/services` 保存选中项目。该范围是医生全局可开展项目；门店项目开放、有效资格、任职、营业时间及已发布排班仍分别校验。页面不把勾选项目等同于可预约号源。

保存采用整组目标项目，必须填写实际核实依据（不填证件号码）。服务端在事务中按机构、相关门店升序、医生的顺序加锁；新任职也按机构、门店、员工加锁，排班创建先锁门店。锁后复核负责人权限，再按差异启用或停用范围。若待移除项目仍出现在该医生未结束的草稿、已发布或暂停排班，返回 409 且零范围修改。变化后的项目编号列表与操作者、依据写入追加式审计，同事务提交；审计失败时范围变更回滚。同值保存不更新 `verified_at`，也不重复写审计。页面保存失败时保留草稿，用户可刷新后核对。

此接口目前仍是排班模块既有路径；OpenAPI 中另有按单项目核实的目标路径，两者尚未统一，不能把现有整组替换接口表述为该目标契约已经实现。后续应收敛端点和授权/审核模型，再考虑停用已有排班所用范围的协调流程。
