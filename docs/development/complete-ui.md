# 完整界面演示（T025-UI-A 扩展）

实现日期：2026-10-27。本轮按“完整界面与交互优先”扩展管理端工作台与患者端主要页面；已有真实接口页面继续复用，不新增后端接口、迁移或权限放宽。

## 2026-11-16 正式工作台首页

- 登录后的默认首页在演示关闭时展示真实快捷入口；仅显示当前角色对应的真实业务路由。系统管理员也能从首页进入账号角色页面。多角色账号的入口取其角色的并集，最终读写权限仍由后端核验。
- 有前台角色的账号通过现有 `GET /staff/appointments?date=YYYY-MM-DD` 读取上海业务日期的预约，展示今日有效预约、候诊、待协调数量和前 8 条当日记录；可刷新并进入完整预约工作台。该接口按服务端授权门店查询，不读取用于生成全部候选时段的 `/staff/booking` 概览。
- 预约列表/概览的门店集合只取同一角色具有 `appointments.assist` 且本人任职有效的门店；兼任其他角色、在其他门店有 scope，不应让前台预约整页 403，也不能读出其他角色门店的预约。尚无医生或项目的旧记录允许以“待安排/—”展示，不把合法的空关联当成接口损坏。
- 其他角色不调用预约接口，不展示猜测的统计。401 进入现有身份复核，403 只显示授权错误；退出、切换账号或变更角色时，旧请求结果不能写入新会话页面。
- 本地演示仍须显式开启；正式模式不显示演示模块导航和虚构指标。此处指标只反映接口返回的当日预约，不等于财务收入或复诊任务总量。
- 当前 `/staff/appointments` 尚无服务端分页；首页只显示前 8 条，但接口仍返回授权门店当天全部记录。课堂虚拟数据可用，日后大规模运行需改为服务端分页或专门的最小统计接口。
- 本节为当前行为；下方“页面清单”的“经营工作台仅本地演示”保留 2026-10-27 的历史快照，不再描述当前正式首页。

## 启动与入口

### 管理端

```powershell

$env:Path = 'D:/DevTools/node-v24.22.1-win-x64;' + $env:Path
npm run dev
```

- 正常入口：`http://127.0.0.1:5173/`，需要员工登录；登录后进入“经营工作台”。

### 患者端

- 首页：门店、医生、下一次就诊、快捷入口、最近就诊。
- 门店详情：地址、电话、营业时间、服务标签、就诊提示。

- 我的预约：待就诊/历史、预约详情、选择新时段并确认改约、取消；状态同步到首页下一次预约。

- 患者端演示开关：首页显式开启/关闭；关闭后各演示页不展示样例，刷新/重启重置。

### 跨页面演示状态

- 管理端预约、代预约、工作台、日历读取同一 `demoState.appointments`；新增/取消/确认/签到立即反映到列表、工作台和日历。
- 患者端 `demo/store.ts` 统一保存小程序运行期预约；首页下一次预约和“我的预约”读取同一状态，确认预约后真正新增，取消/改约更新同一条记录。
- 两端各自内存一致，**不宣称管理端与小程序实时共享**。

## 真实与模拟边界

### 真实接口

- 管理端 `机构门店`：`/branches`，现有门店列表/详情/创建/生命周期接口。
- 管理端 `员工管理`：`/staff-members`，现有员工列表/详情/建档接口。
- 管理端 `账号角色`：`/admin/accounts`，现有账号与角色接口。
- 患者端登录、建档、绑定：保留原 `authFlow`、微信登录与绑定凭证流程，未改服务端契约。
- 正常模式仍服从服务端授权；演示入口不绕过 API 权限。

### 本地模拟

- 管理端工作台、预约接诊、患者与复诊、诊疗与收费、采购与成本、基础设置中的演示模块。
- 患者端首页、门店、医生、预约、我的预约、就诊/复诊、费用/发票页面。
- 所有演示页面有“演示数据 · 本地模拟，未写入后台”标识；操作只改变内存状态，并提示未写入后台。
- **不伪造真实支付、正式发票、医疗资质或真实经营收入**：金额/发票均明确为演示；资格摘要不替代真实审核。

### 演示数据一致性
