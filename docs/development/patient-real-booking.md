# 真实排班与预约（本地开发）

实现日期：2026-10-28。当前真实链路：owner 发布排班 → 前台真实代约/签到/取消；患者真实读取排班、提交预约、取消和改约。

## 环境

- 后端：`DB_URL=jdbc:postgresql://localhost:5432/a_dental_dev`，用户名/密码由本地环境注入；`MOCK_WECHAT_ENABLED=true` 时允许本地 mock 微信。
- 管理端：`admin-web` Vite 代理 `/api` 到 `http://localhost:8080`。
- 患者端：小程序 `API_BASE_URL` 从 `extConfig.apiBaseUrl` 或 storage `a-clinic.apiBaseUrl` 读取，不写死 localhost。开发本地可在微信开发者工具控制台设置：
  ```js
  wx.setStorageSync('a-clinic.apiBaseUrl', 'http://127.0.0.1:8080/api/v1')
  wx.setStorageSync('a-clinic.mockWxCode', 'mock-code-bound')
  ```
  仅本地 mock 使用 `mock-code-bound`；生产环境必须换成真实微信登录和 HTTPS 域名。

## 服务端规则

- 只有 `已发布` 排班可预约；时间必须落在排班内，项目时长不能越过排班结束。
- 提交时检查医生和患者时间冲突；同一排班/时段重复提交返回 409 `SLOT_UNAVAILABLE`。
- 患者自助预约直接确认，渠道为“患者端”；前台代约渠道为电话/现场/微信登记。
- 取消写 `cancelled_at/cancelled_by_type/closure_reason` 并递增版本；签到写 `queue_ticket`。
- 状态使用数据库既有中文状态：`已确认`、`候诊中`、`已取消`、`已完成` 等。

## 当前缺口

## 2026-10-29 患者预约时间与取消边界

患者新预约和改约的新时段必须在服务端当前时间之后；检查在取得目标排班锁后执行，不能回填过去预约。改约失败由同一事务回滚，原预约时段和版本保留。

患者自行取消仅开放给“已确认”预约；候诊中、接诊中及终态不得通过自助取消跳过现场业务流程。需要离店或中止接诊时，应由工作人员按正式流程处理，本批未实现该流程。患者改约、取消先按本人归属检查，不存在与他人预约统一返回404。

本批未完成患者预约/改约的幂等键、版本保护、改约历史链及完整门店/资格/营业区间校验，不代表患者预约模块整体验收。

## 2026-10-29 患者改约历史与防重复
改约请求增加必填 expected_version、reason 和 Idempotency-Key。旧预约转为已改约，原时间、医生、项目及原资源历史保留；新预约 previous_id 指向旧单，继承复诊计划、目的、就诊类型及特殊需求。旧单退出活动、释放资源、新单创建、资源竞争和审计在同一事务中，失败整体回滚。同一幂等键重放返回当前 original/replacement，两者从一条SQL取得；新请求旧版本返回409。复诊计划不因改约完成。

本批改约先按ID顺序锁涉及门店、排班，再锁旧预约；仍需统一前台创建、签到与其他写入路径的整体锁协议，不能声称已消除全部跨模块死锁。政策版本校验（原契约policy_id）、完整资格与营业区间等业务校验尚未补齐，不因本次契约对齐而取消需求。小程序未做开发者工具/真机验证；Word另行同步。

### 2026-11-10 前台签到发号修正

原前台签到用 `max(queue_no)+1` 计算号码，在两笔不同预约并发签到时可能撞号。现改为事务内对 `(branch_id, queue_date)` 的 `queue_counter` 原子递增；首次建计数器时接续同日已有候诊号码。只锁目标预约行，不额外锁排班行；锁前、锁后均复查本店操作权限。只允许预约开始日期与上海当天相同的已确认预约进入候诊；同一预约重复提交返回既有状态，不再次增号。事务失败时预约、候诊凭证和计数器增量一起回滚。隔离 PostgreSQL 全量 381 项通过，其中新增同日/异日、重复、并发和旧号续接场景。

这仍是**前台签到的并发发号修正**，不是完整签到验收：当前接口尚未按 OpenAPI 接收 `expected_version`、线下核验依据、超窗原因和幂等键，也未返回独立候诊凭证；签到窗口配置、患者扫码、60 秒门店码、最小候诊队列及前端相应交互均待实现。现有按钮不得作为这部分已完成的证据。

### 2026-11-10 前台签到契约接线（V020）

前台签到现要求 `Idempotency-Key`、`expected_version` 和现场核验依据；签到窗口取 `branch_booking_config` 的提前/迟到分钟，未配置或超窗时须填写人工办理理由。同日且已确认的预约方可签到，医生有效停诊时拒绝。签到与候诊票、计数器、幂等记录、审计在同一事务；响应返回独立 `QueueTicketResult`（包含候诊号码）。V020 在 `queue_ticket` 增加可空的核验依据和超窗理由，兼容旧票据与后续自助签到；界面提示不得记录证件号码。重复签到返回原票，不再次发号。

这仅收口前台人工签到。患者扫码、门店短效码、候诊队列读取、窗口配置页面仍待实施；文档前段的“尚未按 OpenAPI 接收字段”是本批之前的历史状态。

### 2026-11-10 候诊最小查询

`GET /staff/queue?branch_id=&date=` 已接真实 `queue_ticket`。前台按本店有效已核实任职与 `appointments.assist` 权限读取当日票据；牙医按同角色门店范围与 `appointments.own.read` 只读本人预约。返回仅有票号、预约编号、日期、队列状态与签到渠道，不含姓名、电话、病历或票据核验依据。管理端预约页可按门店和日期查看、刷新。此查询不提供叫号、优先级调整或患者扫码入口。


### 2026-10-29 资源维护保护
共享资源分配器只分配可用牙椅；存在有效禁用记录且禁用开始早于预约结束时，不分配该资源。预计维护结束不等于已恢复，必须显式解除。此规则同时作用于患者、前台创建及患者改约。独立设备按项目需求分配、与维护写入并发的统一锁协议仍待完善，不能声称资源管理全部完成。
