## 建议顺序

1. 先保证课堂可演示的已实现主链路：前台预约/签到 → 医生接诊 → 虚构就诊记录与复诊计划 → 对应页面读回；每一步用用户确认的虚构资料，避免改动预约 941 的临床事实。
2. 完成公网角色验收：负责人配置冲突提示、双账号店内沟通，以及库管/财务演示账号的受控激活与各自权限边界。
3. 对微信真机条件单独决策并验收；若域名和 AppSecret 来不及，交付材料明确写“网页云端可访问、小程序仅本地开发者工具演示”，不要声称双端云端已打通。
4. 验收资格审核入口后继续补任职与异常登记页面，再扩复诊更正、政策、出库及资产成本；相应 Word 和 OpenAPI 只写已实现事实与清楚标注的目标设计。
